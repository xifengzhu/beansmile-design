DESIGN AGENT RUNTIME · 运行在 Codex / Claude 中

把设计过程变成可验证的交付

beansmile-design 从业务目标、用户任务和目标平台出发，把产品需求转化为可点击、响应式、高保真的 HTML 原型，以及包含决策依据、截图、评审结果和验收报告的可审计交付包。

边界声明：它不是生产前端框架，也不直接生成生产级 Web、原生 App 或小程序代码。项目重点解决的是设计过程的一致性、可追溯性和质量验收。

01 · CORE

核心能力：五个组成，一条流水线

Skill 提示层写下的每一条质量承诺，都有对应的机器门禁强制执行；创作与评审分离，避免创作方自行判定通过。

1 + 5 + 21 个 Design Director · 5 个流程 Skills · 2 个只读评审

  • 01 Design Director 维护任务状态、调度各阶段、记录用户确认并作出最终设计裁决。
  • 02 5 个流程 Skills 完成需求研究、UX 架构、视觉系统、HTML 原型和决策记录。
  • 03 2 个只读评审 分别执行规范审计和视觉评审，避免创作方自行判定通过。
  • 04 版本化依据库 管理 WCAG、平台规范、设计工艺和行业规则。
  • 05 可执行质量门 校验上下文、字段权限、阶段转换、浏览器行为、快照、评审和最终交付。
02 · WORKFLOW

工作流：专业模式与快速模式

两种模式共享同一套质量门。快速模式缩短确认过程，但硬性质量要求一条不少。

专业模式 --mode professional

完整阶段链：三个用户确认门、执行候选竞争与双评审，适合范围复杂、需要逐步对齐的设计任务。

  1. 需求研究 → 产出 brief.md 确认门 A：需求与成功标准
  2. UX 架构 → 产出 flows.md 确认门 B：任务流与页面范围
  3. 视觉系统 → 产出 design-tokens.json 确认门 C：视觉方向
  4. HTML 原型 → 执行竞争选出赢家，再截图自评迭代
  5. 双评审 → 规范审计 + 视觉评审，只读冻结快照
  6. 最终验收 → npm run accept 逐维度机器判定

快速模式 --mode quick

适用于范围明确的简单页面：缩短需求和视觉方向的确认过程，直达原型与评审。

  • 不跳过目标平台与关键状态覆盖
  • 不跳过 WCAG 2.2 AA 与真实截图验证
  • 不跳过控制台错误与内容溢出检查
  • 不跳过决策依据记录与双评审
03 · PLATFORMS

平台支持与验证边界

支持 5 类目标平台，验证能力如实分级——能被浏览器自动化验证的和只能近似表达的，界限写清楚。

--platforms 取值：web、mobile_web、ios、android、mini_program，多个值用逗号分隔。
平台验证方式说明
Web 完整浏览器自动化检查 axe 扫描、键盘可达、重排、截图与核心任务场景执行全链路。
响应式移动 Web 完整浏览器自动化检查 与 Web 相同的自动化检查链路，覆盖移动视口。
iOS App HTML 近似 + 人工清单 以 HTML 近似原型表达，系统控件与原生行为需人工清单或真机验证。
Android App HTML 近似 + 人工清单 同上：无法由 HTML 忠实验证的部分显式标注，不假装通过。
微信小程序 HTML 近似 + 人工清单 原生手势、安全区和运行时行为需要人工清单或真机验证。

诚实降级原则：任何无法真实验证的检查（浏览器不可用、原生平台行为）都会显式记为「未验证」，不允许静默记为通过——环境诚实本身就是验收维度之一。

04 · QUICKSTART

快速开始

环境要求：Node.js 18 或更高版本、npm，以及 Chrome 或由 Playwright 安装的 Chromium。以下命令都在仓库根目录执行。

  1. 1

    安装依赖

    本机没有可用 Chrome/Chromium 时，再补装 Playwright 的浏览器。

    npm install
# 可选：npx playwright install chromium
  2. 2

    验证运行环境

    env:check 会真实启动一次浏览器，而不只是检查依赖是否存在。

    npm run check
npm test
npm run env:check
    • exit 0 — Node、Playwright、axe-core 和浏览器自动化均可用。
    • exit 3 — 降级状态：浏览器相关结论只能标「未验证」，任务不能标记完成。
    • exit ≠0 — 其他非零退出码：先修复环境或参数问题。
  3. 3

    启用 Skills

    把 skills/ 下的 8 个 Skill 挂进 .claude/skills 与 .codex/skills，命令幂等。之后在仓库根目录开启会话：Claude Code 输入 /design-director，Codex CLI 输入 $design-director。

    npm run setup:agents
  4. 4

    初始化交付包并启动设计任务

    用下方生成器拼出你的初始化命令；完整流程结束后运行 npm run accept 做最终验收。

初始化命令生成器

填写交付包目录、选择模式与目标平台，生成可直接粘贴到终端的 npm run init 命令。项目名、用户画像与行业为可编辑的默认值。

相对仓库根目录的路径，例如 outputs/demo；outputs/ 已被 Git 忽略。

professional：确认门 A/B/C、执行竞争、双评审；quick：缩短确认、单方向直出，质量门不缩水。

目标平台（至少选一个）

请至少勾选一个目标平台：Web 项目通常选 web，或 web,mobile_web 组合。
