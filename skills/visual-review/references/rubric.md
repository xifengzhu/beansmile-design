# 视觉评审 Rubric（八维度判定标尺）

目的：把"八个维度"变成可复现的判定，消除 LLM 评审天然偏宽松的问题。评审时**逐维度过完全部判定问题**，每个维度至少写出你检查了什么、看到了什么（即使结论是通过）。

## 证据纪律（反宽松机制，硬性）

1. 每条 finding 的 `evidence` 必须含**可核实的具体值**：文件+选择器/区域、以及实测值（px/hex/比值/字重）。"感觉拥挤"不合格；"`index.html .card-grid` 卡片间 gap=8px 而卡片内 padding=24px，区块间距小于内部间距"合格。
2. 快照目录里若有 `audit/screenshots/`，**必须先看截图再读代码**；视觉判断以渲染结果为准，代码只用来定位原因。没有截图时，你的所有布局/观感类结论降为 `note` 并注明"未经渲染验证"。
3. 逐维度检查后 findings 总数 < 3 时，重新过一遍 D/H 维度（细节与完成度）——首轮评审在专业标准下几乎不可能少于 3 条可改进项。确实优秀则为每个零问题维度写出"检查了什么所以认为通过"。
4. **"无错但平庸"必须显式给出**：不构成 blocker，但要以 warning/note 写明平庸在哪（如"层级正确但无任何视觉记忆点：无字号跳跃、无品牌色运用策略"）。verdict=pass 与"有一堆 warning"完全兼容，不要为了 pass 而沉默。

## 判定基准

对照 `skills/visual-system/references/`（字阶/间距/色彩纪律）与 `skills/html-prototype/references/polish-checklist.md`。原型若偏离 design-tokens.json 的令牌（魔法数字），直接构成 finding。

**方向对标（生成↔评审同一本手册）**：评审前先读 `skills/visual-system/references/playbooks/` 中已确认方向的分章（`<Dn>.md` + `_intro.md`，规范 27.7——只读该方向，不通读 8 章），与 `layout-composition.md` 的记忆点菜单（§4）、构成自查（§7）。品牌辨识度与视觉层级维度按手册的"敷衍 vs 到位"判别，evidence 写"哪个关键手法、落地了几处、在第几屏"这类可数事实——评的是执行深度，不是有没有沾边。

## 八维度判定问题与判例

### 1. 视觉层级
- 问：眯眼看截图 3 秒，能否说出"标题、主操作、阅读起点"？一屏是否只有一个焦点级？主操作与次操作的视觉差是否 ≥ 2 个手段（颜色+字重/尺寸）？
- **blocker 判例**：主操作与次操作视觉完全同级，用户无法辨识该点哪个；标题字号 ≤ 正文（层级倒置）。
- **warning 判例**：一屏两个实心主按钮；辅助信息与正文同色同字号导致噪声。
- **note 判例**：层级成立但缺乏节奏（所有标题只差 2px）。

### 2. 版式节奏
- 问：间距是否全部落在 8pt 档位？区块间距 ≥ 2× 内部间距？同类元素间距一致？对齐有无 1–3px 漂移？
- **blocker 判例**：布局漂移/错位导致内容视觉上归属错误的分组（间距失效改变语义）。
- **warning 判例**：区块间距 ≤ 内部间距（页面糊成一片）；同一列表项间距 12/16/20 混用。
- **note 判例**：个别图标与文字光学不居中。

### 3. 字体系统
- 问：全页字号是否 ≤ 7 档且都在字阶上？正文行高 1.6–1.8？行长 ≤ 35 汉字？数字是否 tabular？有无 faux-bold/italic？
- **blocker 判例**：字体系统内部冲突——同一层级两种字号/字族随机混用，正文行高 <1.4 大段不可读。
- **warning 判例**：行长 >45 汉字的面条文本；档位外魔法字号 ≥3 处。
- **note 判例**：大标题未做字距微调。

### 4. 色彩系统
- 问：非状态色相 ≤3？品牌色 ≤10% 且主操作独占实心？灰阶是否染色？状态色语义正确？相邻表面层次可感知？（对比度硬失败归 standards 评审管，这里管**观感与纪律**。）
- **blocker 判例**：已确认的品牌方向被违背（如确认门 C 选了 D1 极简，实做成彩虹渐变）；状态色语义错乱（危险操作用绿色）。
- **warning 判例**：裸灰 #999/#ccc、纯黑文字；品牌色刷满多处背景；两种状态色饱和度明显不协调。
- **note 判例**：阴影未染品牌色调。

### 5. 组件一致性
- 问：同类组件（按钮/输入框/卡片）在所有页面尺寸、圆角、间距、状态是否一致？radius 是否 ≤3 档？图标是否同一图标集、同一描边粗细？
- **blocker 判例**：同一功能组件在两个页面外观完全不同，用户会当成两种功能。
- **warning 判例**：图标混用两个集（描边 1.5px 与 2px 并存）；按钮高度 36/40/44 无规律混用。
- **note 判例**：个别组件 hover 反馈时长不一致。

### 6. 内容适配
- 问：是否用接近真实的内容（无 lorem/测试测试）？极端内容（长标题、空数据、大数字）是否真实放入且不破版？截图上有无裁切、遮挡、溢出？
- **blocker 判例**：占位文掩盖了真实内容长度问题（真实文案必然溢出的布局）；极端内容直接破版。
- **warning 判例**：全部内容都是"理想长度"，未见任何极端样本；日期/金额格式与业务地区不符。
- **note 判例**：个别文案口吻与产品人格不符。

### 7. 品牌辨识度
- 问：遮住 logo，这个界面和任意 Bootstrap 后台可区分吗？确认的方向（D1–D8 或自定义）的关键手法（按 playbooks/<Dn>.md 该方向"关键手法配方"逐条对）是否至少落地 2 处、且在首屏？落地质量按该方向"敷衍 vs 到位"判别属于哪边？layout-composition.md §4 的视觉记忆点是否 ≥2 处？
- **blocker 判例**：交付物与确认门 C 选定的方向明显不符。
- **warning 判例**：方向落地流于表面（playbook 判为"敷衍"侧：如 D3 只换了衬线标题、D8 只加粗了边框）；关键手法 <2 处或全部不在首屏；"零记忆点"的模板感；首屏构成是 layout-composition §1 之外的居中堆叠兜底且无理由。
- **note 判例**：品牌手法只出现在首页、内页全丢。
- evidence 写法：`方向 D3：粗细线系统 0 处、首字下沉 0 处、错位构成 0 处，仅标题换衬线（index.html h1）——playbook"敷衍"判例命中`。
- 纪律提醒：**不得**以个人偏好否定已确认方向——评的是"是否忠实且高质量地执行了方向"。

### 8. 完成度
- 问：四态（hover/active/focus/disabled）齐全？空/加载/错误态真实渲染？favicon/title/选中色这类细节做了吗？骨架屏与内容同尺寸？有无"最后 10%"的粗糙（默认丑影、破图、未对齐的角落）？
- **blocker 判例**：核心流程页面存在明显未完成区域（空白区块、占位框裸奔）。
- **warning 判例**：交互元素缺 hover/focus 态；加载态缺失或与内容尺寸不符。
- **note 判例**：无 favicon；::selection 未定制。

## verdict 判定

- `fail` 当且仅当存在 ≥1 条 blocker（与 findings schema 的一致性约束对齐）。
- blocker 的门槛刻意高（方向违背、层级失效、系统性冲突、破版）；**大多数平庸产出的正确结果是 `pass` + 一串 warning**，Director 依据 warning 决定是否再迭代。你的价值在 warning 的质量，不在 verdict 的松紧。
