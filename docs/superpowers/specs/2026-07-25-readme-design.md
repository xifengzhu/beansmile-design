# README 内容设计规范

日期：2026-07-25
状态：结构已确认，待书面复核

## 1. 目标

为 `beansmile-design` 编写一份中文 README，同时服务两类读者：

- 首次使用项目的设计任务执行者，可以快速理解项目定位、完成环境准备并启动一个交付包。
- 维护和扩展项目的开发者，可以理解运行架构、核心契约、质量门禁与扩展入口。

README 采用渐进式组织：先帮助读者运行，再解释系统，最后提供维护参考。

## 2. 内容结构

README 按以下顺序组织：

1. 项目简介：一句话定位、解决的问题和最终交付物。
2. 核心能力：Design Director、流程 Skills、双评审、证据库和自动化门禁。
3. 快速开始：环境要求、安装、系统自检、初始化示例和基础验证。
4. 工作流：展示从 intake 到 delivered 的完整链路，并说明专业模式、快速模式和确认门。
5. 常用命令：按用途整理 npm 脚本及需要额外参数的 Node 命令。
6. 交付包结构：解释生成目录中的核心产物、上下文、快照、评审与报告。
7. 项目结构：说明仓库内 skills、scripts、evidence、schemas、fixtures 和 templates 的职责。
8. 核心契约：说明 `context.yaml` 单一事实源、canonical Skill ID、字段级补丁门禁和快照版本绑定。
9. 开发与扩展：说明新增或修改 Skill、规则卡、schema 与运行脚本时应同步的位置。
10. 测试与验收：列出系统校验、单元测试、规则校验、召回测试和最终验收方式。
11. 平台边界：明确 Web/响应式移动 Web 与 iOS、Android、微信小程序的验证能力差异。
12. 延伸文档：链接系统设计规范、schema、Skill 注册表和关键参考文件。

## 3. 写作原则

- 使用中文，命令、文件名、字段名和状态值保留原始英文。
- 以当前代码和脚本真实参数为准，不复制规范中的过期命令。
- 快速开始保持最小可运行，不把完整专业流程塞进第一屏。
- 命令示例使用可替换的明确路径，例如 `outputs/demo`，并解释退出码 `0`、`1`、`3` 的含义。
- 不添加无法从仓库确认的许可证、CI、发布渠道、兼容版本或生产承诺。
- 不把 HTML 原型描述为生产代码，也不把未执行的浏览器检查描述为通过。

## 4. 关键事实

- 项目是一套运行在 Codex 或 Claude 中的设计 Agent 运行时，不是最终用户界面。
- 系统由一个 Design Director、五个流程 Skills、两个只读评审和版本化依据库组成。
- 默认输出可点击、高保真、响应式 HTML 原型及可审计交付包。
- 专业模式包含需求、流程和视觉方向三个用户确认门；快速模式减少过程确认，但不降低硬性质量检查。
- `context.yaml` 是任务状态的单一事实源，只能由 Director 通过受控脚本更新。
- 完整自动化验收依赖 Node.js、Playwright、axe-core 和可启动的 Chromium。
- Web 与响应式移动 Web 支持完整自动化检查；原生平台和微信小程序包含 HTML 可验证项与人工核对项。

## 5. 验证方式

完成 README 后执行以下检查：

- 检查 Markdown 中所有仓库内相对链接均指向现有文件。
- 对 README 展示的命令逐项对照脚本参数与 `package.json`。
- 运行 `npm run check`、`npm test`、`npm run validate:rules` 和 `npm run env:check`。
- 若环境检查返回退出码 `3`，如实记录浏览器相关能力为未验证，不把它当作失败或通过。
- 检查 Git diff，确保只包含 README 及本设计规范，不改动无关文件。

## 6. 验收标准

- 新用户可以仅凭 README 安装依赖、检查环境并初始化一个交付包。
- 维护者可以从 README 找到架构、核心契约、测试与扩展入口。
- README 中的命令、文件路径、Skill 数量和平台边界与当前仓库一致。
- 重要限制与降级行为可见，不作超出实现的质量承诺。
- 内容层次清晰，详细系统设计通过链接下沉，README 本身不重复整份规范。
